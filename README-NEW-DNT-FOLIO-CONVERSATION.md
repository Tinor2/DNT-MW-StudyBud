# 4. Project identity and confirmed facts

## Final product name

**Focus Friend**

StudyBud is a historical working name only. The final product is broader than a study assistant: it supports management of stress, workload pressure and neglected routines associated with study.

## Target market

Primary target market: **upper-high-school and university students**.

Early-career workers may be mentioned only as a possible secondary market.

## Product form

- A physical desk companion with a 480 × 480 circular interface.
- Operated using a rotary encoder with press input.
- Supplemented by a responsive web companion.
- The web companion works on desktop and mobile-width browsers.
- It should not be described as a separately packaged native mobile application.
- Accurate wording: “a responsive web companion designed for desktop and mobile use.”

## Implemented feature set

- Home/menu navigation.
- Timer and presets.
- Todos.
- Water tracking.
- Guided breathing.
- Manual sleep logging.
- Sedentary/stretch breaks.
- Settings and backgrounds.
- Warm night-light/Reading Light setting.
- Points, goals, seeds, streaks and plant/Tamagotchi progression.
- Device/web connection and shared system state.

## Sleep wording

Sleep is manually logged. The user starts the log when going to sleep and ends it after waking.

Use “sleep logging” or “user-recorded sleep duration”. Do not claim automatic sleep-cycle tracking or detection.

## Physical manufacture

- Entire enclosure and dial system are described as 3D-printed PLA.
- Superglue was used.
- M3 screws and brass threaded inserts were used.
- Generic rotary encoders were purchased from Amazon.
- Existing evidence includes final CAD, section/exploded drawings, failed prints, screen-carrier development, soldering, wiring and assembly photographs.

## Power arrangement

- Final arrangement: wired USB-C.
- This deliberately replaced a rechargeable battery concept.
- Reason: Focus Friend is intended to remain a constant background presence on a desk; regular recharging would add maintenance and conflict with that role.
- Described connection chain: ESP32 screen assembly UART connector → USB-A adapter → USB-C adapter/cable.

## Removed/reduced features

- Haptic feedback and speaker: removed due to available microcontroller/display pin limits.
- Microphone support: removed; exact reason still requires confirmation.
- Bluetooth: removed; exact reason still requires confirmation.
- Larger dial system: reduced to the simpler final arrangement.
- Apple Watch/wellbeing app/sleep-tracker integrations: removed; exact reason still requires confirmation.

## Outside assistance

Outside assistance was limited to the initial ESP32/display setup. Waveshare support identified or clarified the firmware/software required for the board to work with a Macintosh computer. This must be acknowledged.

# 12. Band-6-oriented folio logic

The folio should demonstrate this chain repeatedly:

> Need → investigation → conclusion → design decision → development/test → applied change → evaluation

The strongest marking emphasis is Project Development and Realisation. Avoid turning the folio into:

- a diary;
- a screenshot dump;
- a component catalogue;
- generic research that did not influence a decision;
- unsupported final claims.

Every major development spread should answer:

1. What was being investigated or solved?
2. What evidence or test was used?
3. What was concluded?
4. What changed because of that conclusion?
5. How did the change improve or constrain the final product?
